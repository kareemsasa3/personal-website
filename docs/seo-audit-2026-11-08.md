## Architecture and route review

- React routes are defined in `web/src/routes/index.tsx`; immersive animation and Rhythm Lab routes bypass the standard layout. Navigation comes from `web/src/data/navigation.ts`.
- `web/src/data/routeMetadata.ts` supplies title, description, route identity, canonical identity and sitemap eligibility. `App.tsx` updates document, Open Graph, Twitter and JSON-LD metadata during client navigation.
- `web/vite.config.ts` builds route-specific HTML bodies and metadata, then replaces the public sitemap with one generated from canonical metadata. Case studies and writing ship substantive text before JavaScript executes. Interactive simulation shells describe the model and link to its section; they do not pretend to run without JavaScript.
- Canonical identities are slash-free internally; public canonical URLs use the trailing slash that nginx serves for directory indexes. Normalization already handles trailing slashes, queries and fragments. Existing tests protect this behavior.
- `/work` remains an alias for Experience. `/games` and `/games/*` retain the existing client redirect component and destination mapping. No route was renamed or removed. Adding directory shells for Annals and Work gives their bare paths the existing nginx directory-to-trailing-slash normalization; React continues to accept both spellings.
- Robots allows general crawling and OAI-SearchBot, and disallows GPTBot. No general search-engine block was found in repository rules.
- All five raw animation `piece.html` documents, including ANASTASIS, deliberately use `noindex, nofollow`. Their surrounding public routes are indexable and canonical. The two `noindex` exclusions in the supplied snapshot cannot be mapped to these files without URL-level evidence.
- The committed AI-context files (`web/public/ai/context.md`, `web/public/ai/site-manifest.json`) are generated from route metadata by `web/scripts/generate-ai-context.mjs`. They were regenerated on this branch so they list Annals and the new document titles.
- Existing schema is restrained: Person/WebSite, WebPage/ProfilePage, breadcrumbs, case-study CreativeWork, published Article and public-repository SoftwareSourceCode. Candidate WebPage metadata agrees with the HTML; CreativeWork and Article names keep their authored titles. No new rich-result type, fabricated date, rating, FAQ or outcome was added.
